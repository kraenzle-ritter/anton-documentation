# Selection and bulk actions

Several units of description can be ticked in result lists and processed
together. At present there is **one** action for this: [moving](hierarchy.md).

!!! note "Only in some archives"
    Bulk actions have to be enabled and require the `admin` role. They are not a
    standard feature; the setting cannot be changed in the admin area, and with
    Anton as a Service, k & r is responsible for it. Anyone who does not need
    them can additionally switch them off in their own profile.

## First the action, then the selection

The order is the reverse of what one is used to and is the most common stumbling
block:

1. **First** choose the action in the **actions** selection field — available is
   **move**. Before that, nothing can be ticked; the boxes have no effect.
2. **Then** tick the units. The icon with the clipboard list above the result
   list — it shows the number of units selected — allows the current selection to
   be inspected at any time.
3. Carry out the action. **Clear** discards the selection.

!!! warning "Changing the action clears the selection"
    If the selection field is changed afterwards, the previous selection is
    discarded. The action therefore has to be determined before ticking.

## What can be selected together

Only units that **could be siblings**. As soon as a file is ticked, a fonds can
no longer be added — Anton prevents selections that could not be moved together.
Anyone unable to tick a unit should therefore check the levels already selected.

If a move operation is already under way, the selection is locked until it has
been completed or cancelled.

## Not the same as the order basket

The selection and the [order basket](cart.md) look similar and are nevertheless
two separate lists that never influence one another. The selection serves
editing, the order basket ordering. A selection cannot be transferred into the
order basket.
