# Import

## Migration from another database

Migrating from one database to a new one always involves a relatively large effort. The data has to be mapped, in part prepared and/or reworked, and where necessary corrected. At the same time, a migration reveals weaknesses in the data and the data is homogenised. In this respect, a database migration offers an opportunity to improve data quality.

Which migration strategy is most suitable has to be decided case by case. We have successfully carried out the following approaches with Anton:

1. Export of the old database to Excel files – Excel import into Anton  
2. Export of the old database to EAD files – EAD import into Anton  
3. Direct transfer of the data from the old database  

Methods 2 and 3 require scripts to be written and/or adapted.

## Import from Excel

Anton has an elaborate, well-documented Excel import. Larger cataloguing campaigns at the same level of description are also frequently carried out in Excel. The Excel file is then validated and the data imported into Anton.

Digital objects (photographs, documents, etc.) can be imported via the Excel import as well.

## Import from SIP (eCH-0160)

Anton supports the import of SIP packages in the eCH-0160 format. This makes it possible to transfer archival holdings managed in other systems into Anton. See also [SIP import in Anton](../user/sip.md).

## File shares

There is an import for file shares. Anton reconstructs the hierarchy of the file share. The individual files become items. This import is currently not yet available through the browser.
